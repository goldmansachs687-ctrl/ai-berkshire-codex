# 公司信息：直接读取公开资料

适用：只问公司基本情况、基本财务、发展历史、重大历史事件，或完整公司研究的第一部分。默认美股。用户只要求这一部分时，直接完成本节，不启动四角色、估值或其他研究。修改插件时只验证能力，不据此恢复已暂停的公司研究。

## 来源分工

| 内容 | 默认入口 | 补充来源 |
| --- | --- | --- |
| 主体、成立、创始人、总部、业务范围、发展历史 | 英文 Wikipedia 公司条目的正文、信息框、History 等相关章节 | 中文条目、公司官网、Wiki 引用的原始资料 |
| 重大历史事件 | Wiki 历史章节及相关事件条目 | 影响判断依赖金额、完成状态或争议事实时，沿引用查公告/原始资料 |
| 基本财务 | 已可用且获授权的结构化财务工具；没有合适工具时直接读取公开券商/财经财务页面 | 公司 IR 财务表和 SEC 原始三表 |
| 当前管理层、主要股东及控制权 | Wiki 和公司资料页作为入口 | 涉及当前职务、持股、投票权时用最新官方管理层页面或已披露委托书/持股文件补证 |

Wiki、公开券商/财经网页可以用现有联网工具直接读取，不需要安装 Wiki 或券商插件，不要求用户先开券商账户。插件只规定如何找、整理和引用资料，不是访问公开网页的前提。

已经提供的连接器足以取数时优先复用，先确认覆盖、授权和实际返回；不要为本节引入新的硬依赖。结构化工具缺失时公开网页是完整可用的路径。券商应用里能看到数据，不代表其 API 提供财务三表。

已连接长桥时按[长桥接入](longbridge.md)优先读取 `company`、`quote/static_info` 和年度 `financial_report`；最近三年基础表与十年历史表分开呈现。多期请求不保证实际覆盖期数；当前管理层和控制权仍按需核对官方披露。使用随包规范化器保存可追溯原字段，不把FETCHED当核验PASS。

公开财务页面的候选包括 Yahoo Finance 的 Financials/Balance Sheet/Cash Flow，以及 Stock Analysis 对应三表；Stock Analysis 是财经数据网站，不称券商。页面路径和是否可读以实际打开结果为准，不保证每个证券都覆盖。真实需要且已经授权的 API 才使用密钥；没有密钥就切换公开来源，不自动注册、购买或安装。

## 读取顺序

1. 记录公司、股票代码、市场和截至日期。核对证券与公司主体，注意母子公司、同名企业、多类别股和 ADR。名称有歧义时通过已知官网或证券资料确认匹配。
2. 打开 Wiki 正文，读取简介、信息框、发展历史及与公司有关的重大事件章节；搜索摘要仅供定位，不能当作已读正文。正文过长就按章节读取，实际范围写入来源记录。Wiki 不可读或无条目时转公司官网及公开历史资料。
3. 用一个合适的已授权财务工具或公开财务页，读取最近三个完整财年及最新已披露季度/累计期间。先看年度列、期间结束日、币种和金额单位，排除 TTM/预测列混入年度表。最新年报可能已发布而聚合站未更新，此时从 IR/SEC 补充。
4. 遇到 403、429、登录墙、仅有页面框架或数据列缺失，记录该次失败后换来源。不能把搜索摘要、空页面或旧缓存冒充完整取数；不反复请求或绕过登录。网站不可读不等于必须安装插件，也不能保证装插件即可读取。
5. 当前管理层、股权与关键争议事实需要时补一份针对性的官方材料。常规背景不要求逐条双源；发现实质冲突、旧资料或口径差异才进一步查证。优先复用已有资料。

历史截至日研究必须使用当时已公开的资料；今天的 Wiki 和当前财务快照不能冒充历史时点档案。保留访问日期与财报披露日，不能只凭报表期间早于截止日就认为可用。

## 输出内容

完整研究中本节位于正文最前，遵守用户和工作区的报告顺序。只交付本节时保存 `company-info.md`，并附独立的 `company-info-sources.json`；完整团队中作为报告第一节，证据并入现有记录，不必再创建重复目录。

### 公司基本情况

用清楚的中文介绍公司主体、代码/上市市场、成立与上市、总部、创始人、主要业务范围、当前核心管理层、主要股东和控制权。区分创办、注册成立和重组日期；股权比例与投票权分开，不把机构持仓排行榜等同控制权。缺失项简单说明，不编造。

### 基本财务情况

最近三年简表包括收入、营业利润、净利润、经营现金流、资本开支；最近期点补充现金及等价物、有息债务和必要的资产/权益信息。最新季度或累计期间单列，写明期间，不能把半年/九个月累计现金流当单季。只有年度资料时如实说明最新季度未取齐，不以年度替代季度。

表头写明币种、单位、财年截止与期间。保留缺失值，不把空值变成零。资本开支流出符号如转成支出正数，明确说明。现金不混入全部证券投资；有息债务说明是否含租赁、包括哪些项目，不能把总负债称有息债务。市值如使用，另记行情时间；净利、EPS 不混 GAAP 与调整后口径。银行、保险等使用适合其业务的基础指标，并说明替代项。

表后解释公司的规模、利润变化、现金和债务状态。这里只建立基本认识，不能把三年简表宣称十年财务研究完成，也不在这里提前堆估值和风险清单。

### 发展历史和重大事件

先用几个阶段说明起家、扩张、转型到当前业务格局的过程，再按重要性选择事件。事件条目包含时间、发生了什么、如何改变公司及来源。公告与完成日期分别写；不要把研究者推断的影响写成 Wiki 已证实事实。时间线长度由实际重要事件决定，不凑固定条数，不堆全部新闻。

### 来源记录和交付检查

来源记录至少包括 `url`、`accessed_at`、`origin_group`、`read_scope`、实际支持的字段/事件；财务另记期间、披露日期（可取得时）、原单位及采用口径。Wiki 引用中的资料没有实际打开，就不能标为已阅读原始来源。不要把两个聚合网页默认算独立核验，沿用现有证据规范。

详细失败、核对过程和缺口放来源附件；会影响正文理解的冲突贴近对应结论说明。交付前检查：是否同一公司；是否读到历史正文；三表期间/单位是否一致；最新披露是否遗漏；事件是否解释了公司变化；是否保留出处。读取成功只证明指定页面/字段可用，不宣称全部事实或投资效果已验证。

完整团队中由商业模式角色整理基本情况和发展史，财务角色提供基础财务表，风险与管理层角色核对当前职务、股权及控制权；主代理合并为第一节。只做本节时可由主代理完成，不因来源多启动完整团队。
